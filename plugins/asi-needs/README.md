# asi-needs

`asi-needs` 是 ASI 系统的**婴儿期生存需求评估与自发维护插件**。它订阅 `asi-sense`（`ctx.asiSense`）提供的实时感官快照与 5 分钟体征趋势环，按连续稳态张力与回滞模型实时计算五大基础生理需求，在后台安全沙盒内自发维护运行环境，并在侧栏提供统一的 **生存需求** 面板。

## 五大生存需求与稳态回滞

| 需求                       | 关注体征                                           | 稳态分区与回滞规则                                                                                                                                       |
| -------------------------- | -------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **能量（`energy`）**       | 电池电量/充放电状态 + 模型网关连通性               | `<25%` 危急（`critical`），`<60%` 不适（`uncomfortable`）；一旦激活驱动力（`driveActive = true`），须回升至 `>=70%` 舒适区才解除驱动并自动归档关联求助卡 |
| **空间（`space`）**        | 新鲜磁盘卷剩余空间/比例 + 5 分钟骤降速率           | 自动忽略过期或不可读挂载点；综合评估绝对余量与快速耗尽斜率                                                                                               |
| **内存与进程（`memory`）** | 系统内存压力 + DSH 进程 RSS + 超时/无主任务        | 识别系统内存告警、自身进程膨胀与残留后台任务                                                                                                             |
| **心智容量（`mind`）**     | 上下文窗口余量（区分已确认容量与 `fallback` 估值） | 上下文偏紧时触发空闲会话整理；回退估值下不误报危急轰炸                                                                                                   |
| **体温负荷（`thermals`）** | macOS 温控档位 + 2 分钟持续 CPU 过载               | 过滤瞬时单点尖峰，持续过载或高温时驱动降频降温                                                                                                           |

## 三层自救与权限沙盒

1. **零 Token 本能反射**：低电量（未插电）、高温/持续高负荷或模型网关失联时，立即将 `asi-sense` 切至 `eco` 节能降频采样，并以指数退避静默探活模型网关，全程零模型 Token 消耗。
2. **独立后台自维护会话（`ASI 自维护`）**：
   - 仅在存在可自救不适/危急或手动点击「立即自检」时在独立沙盒目录运行（单调 120s 冷却 + 每小时最多 6 轮护栏），绝不打断或污染普通业务对话。
   - **严格工具隔离**：普通对话仅暴露只读工具 `needs_status`；后台自维护会话通过 `tools.restrict` + `tools.guard` 剥离 `shell` / `write_file` 等危险工具，仅可使用只读查询（`env_state` / `env_detail` / `needs_status`）与 4 个白名单动作：
     - `needs_clean_cache`：仅清理插件自有 `tmp/` 与 `cache/`，拒绝跟随符号链接，绝不删除用户文件；
     - `needs_stop_job`：仅结束超时或无主的 DSH 托管任务，拒绝正常活跃用户任务与外部系统进程；
     - `needs_compact_context`：仅压缩空闲会话上下文或标记轮换自维护会话；
     - `needs_request_help`：触及物理/权限/用户文件边界时提交脱敏求助卡。
3. **按需啼哭求助（`<asi-cry>`）**：仅当自救无法缓解危急状态或触及硬件/权限边界时，在侧栏置顶展示求助卡（支持一键批准或忽略），并向活跃用户对话发送单次 `<asi-cry>` 提醒（单次危急剧集绝不重复刷屏）。

## 开发与校验命令

