## 4. 宿主到客户端数据流

Host `AsiSenseSpike extends TypertRemoteService` 注册 `asiSenseSpike`；
`watch(signal)` 是 `@Remote({ mode: 'stream' })` AsyncIterable。
Host 每 2s 用一个共享定时器采样；不是浏览器每 2s 发 HTTP 轮询。
CPU 用 `os.cpus()` 两次时间差；内存用 `totalmem() - freemem()`；磁盘用 `fs.statfsSync()`。
采样结构包含 `{ cpu, memUsed, memTotal, diskFree }`，另有 seq/time、token 与 helper 事件。
注意此内存算法把 macOS 可回收缓存也计入 used，不能据此声称真实内存压力接近耗尽。

Client 把生成的 contribution 用 `ctx.remote.$mount()` 挂载，再在
`ctx.inject(['remote.asiSenseSpike', 'slots', 'locale'], ...)` 内调用该 namespace。
直接用未声明 namespace 的父 ctx 会报 `cannot get property ... without inject`，已修正。

真实 unary Remote 取证命令（浏览器同源、有本任务的本机会话认证）：

```js
await page.fetch('/api/asiSenseSpike/snapshot', {
  method: 'POST', headers: { 'content-type': 'application/json' },
  body: JSON.stringify({ type: 'client-request', rpcId: 'p0-snapshot-proof',
    method: 'asiSenseSpike/snapshot', payload: { args: {} } }),
})
```

返回 HTTP 200 / `result.ok: true`，seq 108，cpu 0.26486013986013984，
memUsed 68360388608，memTotal 68719476736，diskFree 193960448000。
[原始脱敏响应](p0-shots/remote-snapshot.json)。
早期 DOM 连续采样为 `#5087 19:23:57.291Z / CPU31.2%` 到
`#5088 19:23:59.293Z / CPU34.5%`，见 stream-before/after.json。
早期两个同名 PNG 实际哈希相同，不能算视觉变化证据。
最终用两次真实 CDP `Page.captureScreenshot` 复验：
[图 A](p0-shots/stream-proof-a.png) 为 `#15 19:38:03.617Z / CPU34.8%`，
[图 B](p0-shots/stream-proof-b.png) 为 `#18 19:38:09.622Z / CPU29.1%`。
肉眼确认面板数值改变、文件哈希不同，PNG 分别 193920 / 194505 字节；
[取证方法和哈希](p0-shots/stream-proof.txt)。没有对截图内容做后期修改。

独立包构建命令：`pnpm --dir <P0> run build`，实际完成 host tsc、
`WorkspaceTypertGenerator` 生成、esbuild Client bundle；`generate-typert: wrote 1 artifact(s)`。
未手写 wire descriptor，但外部生成器需要 analyzer-only ambient shim 才能避开整个 DSH 源码图。
这不是生产级独立插件 SDK 方案。建议 M2 固定官方生成器版本并完善外部类型映射。
结论：运行通，生成/打包工程化只验证到一次性 spike 水平。

## 5. token 读取与 contextWindow

当前 Session 来自显式选中的 live Agent 的 `agent.session`，并非用最新创建会话冒充 UI 当前会话。
Host 实际调用：

```ts
ctx.tokenMeter.contextPressure(agent.session)
ctx.sessionProjections.snapshot(agent.session, ['tokenUsage', 'contextPressure']).values
const route = agent.model.current()
await ctx.llm.resolveModelInfo(route.provider, route.model)
```

`contextPressure()` 本身只返回 pressureTokens / contextWindow；
projectedTokens 从同名 projection 读取，不能把 `measure().totalTokens` 冒充该值。
在模型调用前 pressure/window/projected 缺失，面板显示 `—`，usage 四桶为 0。

```json
{
  "pressureTokens": 27370,
  "contextWindow": 1000000,
  "projectedTokens": 27383,
  "modelContext": 1000000,
  "usage": { "uncachedInputTokens": 54661, "outputTokens": 18,
    "cacheReadTokens": 0, "cacheWriteTokens": 0 }
}
```

这是 [remote-snapshot.json](p0-shots/remote-snapshot.json) 中的真实值；
modelContext 由 `resolveModelInfo(...).context.contextWindow` 提取。
面板：[上下文已用/窗口与会话用量](p0-shots/tokens-after-followup.png)。
pressure 是最后一次 provider prompt，projected 是下一请求估计，累计 usage 不能相减当上下文余量。

**重要限制：**本次故意不填模型容量。magpie `/models` 广告 256000，
DSH `llm-pi-ai` 却使用其 `DEFAULT_CONTEXT_WINDOW = 1_000_000` 回退值；
模型发现结果不会自动持久化成路由配置。因此“有值”不等于“真实容量”。
替代方案：把发现并确认的 `models[].contextWindow: 256000` 显式写入 profile，
或接入有真实容量的模型目录；标记来源为 configured/catalog/fallback。
本次没有修改容量后二次发模型请求，也未验证账户余额接口。结论：部分。

## 6. inject、followup、source.kind 与当前会话

通过真实面板按钮依次触发 `agent.inject(createUserMessage(...))` 和 `agent.followup(...)`。
这里只注入固定的合成 marker，不发送应用名、窗口标题或 helper 数据。
用以下命令从隔离 profile 的压缩持久日志提取白名单字段：

```sh
node spikes/p0/scripts/capture-session.mjs docs/spikes/p0-shots/inject-idle.json
# 点击 followup，等 idle 后：
node spikes/p0/scripts/capture-session.mjs docs/spikes/p0-shots/followup.json
```

脚本只读取本次固定 synthetic session，不读取其他用户会话，不导出系统提示或窗口信息。
真实输出摘要：

```text
inject-idle.json:
  capturedAt = 2026-11-15T19:32:34.931Z
  modelRequests = 1; turnStarts = [1]; turnEnds = [completed]
  seq19: target=next-step, source.kind=environment
  message = P0 synthetic environment marker: SPIKE_INJECT_731. Do not run tools.
  environmentMessages = []

followup.json:
  modelRequests = 2; turnStarts = [1,2]; turnEnds = [completed,completed]
  seq20: target=next-turn, source.kind=environment
  seq25: user/message marker, source.kind=environment
  seq26: user/message followup, source.kind=environment
  seq28: assistant/message = SPIKE_INJECT_VISIBLE
```

inject 在 `19:31:55.415Z` 入 next-step inbox，至 39.516 秒后的 capture 仍只有第 1 轮，
面板仍为 idle：[idle 注入截图](p0-shots/inject-idle.png)。
followup 在 `19:32:36.104Z` 立即创建第 2 轮，面板曾显示 running，随后约 3.1 秒完成。
模型回复 [SPIKE_INJECT_VISIBLE](p0-shots/followup-reply.png)：
idle inject 不单独唤醒，下一轮确实读到 marker，followup 确实唤醒新一轮。

自定义 kind **支持**：`MessageSourceMap` 是声明合并扩展点，在插件中声明
`environment: { kind: 'environment' }` 后正常编译，无需 `as 'user'`，
持久日志也保留 `environment`。UI 对未知来源显示通用“收到执行请求”，不会显示为普通手输文本。

当前会话的边界：
- Client root standard prop `useSessions` 可读 `retainedBy.mainView`，本次用它定位 UI 选中会话。
- Client 显式把 session id 传给 Host；Host 用 `ctx.agents.get(id)` 得 live Agent，再取 `.session`。
- Host 的 `agent/created` / `agent/status` 只是生命周期/运行状态，不是“用户最近在看谁”的权威来源。
- 多个浏览器/多会话不存在一个已证实的全局“当前用户会话”；生产版应制定目标选择策略，不能广播或仅按 created 顺序投递。

曾用 analyzer shim 的 `Agent` lookup 参数生成 Remote，因 SessionId 的严格定义不匹配得到
`gateway/provider-mismatch`。最终改成普通 JSON string sessionId 并在 Host 显式解析，
Select / inject / followup 均真实成功。**这只证明当前字符串 ID 路线，
不证明 shim 生成的 Agent lookup 可发布。**结论：通；生产应修复生成类型映射或保留显式解析。

并在当前 focused **window 元素**订阅 `kAXTitleChangedNotification`；
焦点切换时替换窗口订阅，失败输出 unsupported 与 AXError，不用轮询补偿。

产品应把 `axTrusted=false` 映射成 denied 并显示设置入口。
只观察到温控初值，未人为加热机器验证温控变化；保留为 M2 实机用例。
没有单独证实“同一窗口仅改标题、不换焦点”的通知触发；已有订阅和窗口事件不能替代这个用例。
结论：部分，应用激活/窗口初值/接入链路通，通知边界仍需补验收。

```js
const d = JSON.parse(readFileSync('<P0>/tmp/dsh-home/storages/workspace.json', 'utf8'))
console.log({ unit: d.unit, globalInitialized: d.global.initialized,

```

默认 single JSON layout 的物理位置是已配置 root 下的 `<domain>.json`；
per-record layout 和 SQLite 的布局不同，不能假设每插件自动有一个目录。
推荐 asi-sense 用独立命名领域保存规则/开关，状态事实先留内存；消费方用 effect 关闭 domain。
结论：服务和已有持久落盘通；**本次没有为 spike 新建领域，也没有做 asi-sense 规则重启恢复测试**，
不能把 workspace 落盘证据当作未来规则持久化测试。
